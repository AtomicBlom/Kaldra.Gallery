# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

The engine's demo gallery and GPU test bed, built on checkouts of the engine and Sirrow beside it (`README.md`, "Building"). The engine's own `CLAUDE.md` has its conventions, which hold here too.

## Tests

- Golden-image + cross-backend parity are in-process GPU-gated tests over `Kaldra.Gallery`: `GalleryGoldenTests` renders the tracked demos offscreen and diffs them against committed baselines under `Kaldra.Gallery.Tests/Goldens/` (`KALDRA_GOLDEN_UPDATE` regenerates them; `tools/golden.ps1 -Update` wraps that), and `GalleryParityTests` diffs Vulkan-vs-DirectX12 renders directly. Both SKIP when the backend they need is absent, so CI (no GPU) skips them. The UI demos are in both: `GalleryCapture` shows a demo's own page (`IDemo.OverlayContent`) in a chrome-hidden shell and replays its scripted click (`IDemo.CaptureClick`), exactly as the browser's capture mode does, and `UIDemoCaptureTests` fails if a UI demo's UI stops reaching the frame (two blank-UI frames would otherwise pass both). The baselines are GPU-specific: regenerating them updates every tracked demo, so to add one, keep only the new PNG and restore the rest.
- **Targeted controlled tests** complement the gallery goldens/parity (broad but low-resolution — a failure doesn't say *which* stage diverged): each renders a minimal single-feature scene offscreen to one target, confounds stripped, and asserts one thing. Three flavours — parity **with a control** (`TargetedParityTests`; e.g. the normal-map G-buffer's encoded normal diffed beside the *same shader's* albedo, pinning a divergence to the TBN math not the sampler), **self-consistency** (`RenderDeterminismTests`; a repeat render is bit-identical — what the goldens rest on), and **property/invariant** (`RenderPropertyTests`; group-opacity overlap == non-overlap, tone-map monotonic). Reach for one when a feature is subtle, backend-divergence-prone, or has bitten — not reflexively. Enablers: the offscreen path (`GalleryCapture`), a fullscreen `probe` shader (a pushed RGBA×UV gradient, HDR-capable) for controlled colour/HDR inputs, and `InWorldPanel` for rendering a UI tree to a readable target. **Gotchas:** reason about a cross-backend diff with the parity metric (`ImageComparison.Compare` — a pixel fails if *any* channel exceeds tolerance); `Scripts/Verification/diff.ps1` *averages* the four channels and can hide a single-channel divergence. And guard these against a vacuous pass — two flat/black frames also compare as equal, so assert the render actually has content.
- ⚠️ **Known flake on Windows-on-ARM (Snapdragon X / Adreno), [the engine's #72](https://github.com/AtomicBlom/Kaldra/issues/72):** the full suite can abort the whole process with `0xC0000409` (`STATUS_STACK_BUFFER_OVERRUN`; the faulting module is often `d3d10warp.dll`), with no test summary. The trigger is `GalleryParityTests` (hardware Vulkan + DirectX 12 devices) and `GallerySoftwareAdapterTests` (a WARP DirectX 12 device) running in one process; each passes on its own. It is not caused by your change. On that box, run the GPU classes in separate invocations with `--treenode-filter`, and confirm a suspected regression against `master` before chasing it.
